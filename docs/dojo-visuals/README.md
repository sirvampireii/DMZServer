# Dojo visuals (LM 4.7.68, Phase 1: pictures first)

These pictures are for approval before the dojo generator and the dojo menus are built. Every building in them is
rendered from the same design data the in-game generator will place (`tools/dojo-visuals/design.py`), so a built
dojo looks like its picture.

## What is new, and what it replaces

LM had no structure tooling before 4.7.68: no templates, no schematics, no generator. The first 4.7.68 draft
placed blocks with one-off code. That draft is replaced by the tool below once these pictures are approved.

## Approach: data templates, one placement path (and why)

DragonMineZ's tournament grounds (`OtherworldTournamentGrounds` in dragonminez-2.2) ship a schematic
(`schematics/otherworld_tournament.schem`). Its `Build` class parses the palette and places it one chunk column at a
time under a per-tick time budget, holding chunk tickets ahead of the cursor, with protected bounds and a built
revision.

LM's generator uses the same placement idea with a different source:

- **Templates as data.** Each room and the arena, at each tier and in each style's architecture, is a template of
  symbols: floor, inlay, ring border, wall, pillar, roof, trim, light, accent, glass, mat, decor, greenery, path and
  gallery glass. A style's palette maps the symbols to blocks. The templates are generated by `design.py` and
  exported into the LM jar. A hand-built schematic per style and tier would be 4 x 3 x 8 files to keep consistent,
  and could not be re-rendered into pictures.
- **One placement path.** Every room and arena goes through the same budgeted chunk-column placer, with plot
  spacing, ground flattening, safe spawn and landing points, and arena bounds. An upgrade re-places that room from
  its next-tier template, so it never pastes a different build on top.
- **Built-in checks.** After placing, the tool verifies the build: no floating blocks, no open or cut roofs, a flat
  arena floor, clear sightlines from the gallery to every ring, and safe spawn points. A dojo that fails does not
  generate.

## Styles: one architecture each

| Style | Architecture | Palette |
|---|---|---|
| Ki Masters | Open pavilion: raised floor, white columns with glass between, flat roof and raised clerestory | Quartz, calcite, sky-blue glass, sea lanterns |
| Melee | Japanese dojo: half-timbered walls, hip roof, a second eave from refined up | Spruce and dark oak, white walls, crimson trim |
| Strike Moves | Fortress: thick walls, slit windows, buttresses, crenellated flat roof, corner towers from refined up | Stone and deepslate, iron bars, copper and orange |
| Evasion | Stilt house: floor on bamboo posts, lattice walls, leafy thatch roof, veranda from refined up | Bamboo, mangrove and cherry, moss, green and pink |

Tiers: basic, refined and masterwork. Each tier adds detail: base course, beam band, windows, trim bands, inlay
patterns, taller posts and lights.

## Navigation

The main menu's "Sparring & Dojo" tile becomes "Spar Board" and "Dojo wars" becomes "My dojo". From the main menu:

- **Spar Board (1 tap):** accept, post, and watch are 2 taps; challenging a player is 3.
- **My dojo (1 tap):** visit is 2 taps. Buying an upgrade, the room preview, style and bonus, wars, elites and
  visiting another dojo are 3.

## The layout map

On the LM client the upgrade screen draws the map as colored room blocks: built rooms in their tier color, empty
slots dark, and the room this purchase changes outlined. It is generated from the dojo's real state. This is a new
additive menu element, like the color wheel. KaiPath players see the same map as text rows.

Re-render everything: `python tools/dojo-visuals/render.py docs/dojo-visuals`, then `sheets.py` and
`mock_menus.py` with the same folder.
